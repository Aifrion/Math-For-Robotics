Lecture 2: Linear Systems of Equations

The one-sentence version: A·x = b is the sentence "mix these known effects (columns) in unknown amounts (x) to meet these rules (rows, b)" — and this lecture is how to read it (row view, column view, null space) and how to solve it (elimination, LDU, QR, SVD) without the numerics biting you.

The big picture

Lecture 1 ended with \(v = \Phi\dot q\): hand velocities from joint velocities. This whole lecture is about that one equation shape. The running example everywhere below is a 2-link arm (links = 1) at shoulder 90°, elbow −90°, whose Jacobian system \(J\dot\theta = v\) is

$$\begin{pmatrix} -1 & 0 \\ 1 & 1 \end{pmatrix} \begin{pmatrix} \dot\theta_1 \\ \dot\theta_2 \end{pmatrix} = \begin{pmatrix} 0.5 \\ 0 \end{pmatrix} \qquad\text{"slide the hand right at 0.5, keep its height"}$$

1 · Where robots meet A·x = b

m equations, n unknowns: \(A \in \mathbb{R}^{m\times n}\) maps \(\mathbb{R}^n \to \mathbb{R}^m\). m counts rules, not dimensions of space — a rigid hand can carry up to 6 rules (3 position + 3 orientation), and estimation problems routinely carry thousands.

2 · Anatomy: rows are rules, columns are joints

The single most bug-prone fact in this course:

⚠️ It's the opposite of what you expect: in \(J\dot\theta = v\), each column of A is a joint — the hand velocity that joint alone would cause. Each row is a hand direction — one rule about one component of the hand's motion. x says how much of each column to mix; b holds only the hand speeds you wrote rules for. b = 0 means "every listed speed is zero", not "nothing moves".

3 · The row view: each rule is a line in x-space

Draw each row's equation in the space of unknowns (joint speeds). Row i is the set of all x that satisfy rule i; the solution is the crossing.

🕹️ Try it: the row view of the arm system. Slide b₁, b₂ — the lines slide but never turn. A sets directions; b only picks positions.

💡 The #1 reading error: these axes are x-space (joint speeds), and the crossing point is x, the solution — not b. b never appears as a point in this picture; it hides inside each line's position.

4 · The column view: b is a mix of the columns

Same equation, transposed intuition: \(A x = x_1\,(\text{col}_1) + x_2\,(\text{col}_2) = b\). The columns span a grid of every reachable b (the column space); solving = finding the recipe. Independence is visible: columns pointing different ways cover the plane; parallel columns collapse the grid onto a line, and most b's become unreachable.

🕹️ Try it: drag the column tips and b. Tilt column 2 onto column 1 and watch the whole plane of options collapse.

Independence test cheat sheet: rows independent ⟺ their lines aren't parallel; columns independent ⟺ their arrows aren't collinear; for square A both happen exactly when det A ≠ 0. And n independent vectors are needed to reach all of n-D — two independent arrows in 3-D span only a plane.

5 · Null space: motion the rules can't see

$$\text{null}(A) = \{x : Ax = 0\}, \qquad n = \dim(\text{row space}) + \dim(\text{null space})$$

A null-space vector is a nonzero joint motion producing zero on every listed rule — for the arm, joints moving while the hand (or the ruled part of it) holds still. Dependent columns create it: if col₂ = 2·col₁, then the mix (2, −1) cancels to zero, and (2, −1) is a null direction — one joint doing a job, the other undoing it.

🕹️ Try it: the joint-speed plane split into row space ⊥ null space, with the arm obeying. Tab 3 is the singular straight arm.

⚠️ The null space belongs to the task and the pose: with both rules active, the bent arm has null space {0} — but straighten the arm and a null direction appears while a hand direction becomes unreachable. A singularity is exactly that silent swap. And remember the rules are bookkeeping, not physics:

🕹️ Try it: two identical arms, different rule lists. Same physics, different verdicts.

Singular ⟺ (equivalently): det A = 0 · rank < n · dependent rows · dependent columns · nonzero null space · no inverse. Six phrasings, one disease.

6 · Solving: Gauss elimination & Gauss–Jordan

Subtract multiples of rows to zero out everything below the diagonal, then back-substitute. The slides' example, verified step by step:

Worked example: the slides' 3×3 system (click to close)
$$\begin{pmatrix} 0&4&-1\\ 1&1&1\\ 2&-2&1 \end{pmatrix} x = \begin{pmatrix}5\\6\\1\end{pmatrix} \;\xrightarrow{\text{swap r1,r2 (pivot 0!)}}\; \begin{pmatrix} 1&1&1\\ 0&4&-1\\ 2&-2&1 \end{pmatrix}\!\begin{pmatrix}6\\5\\1\end{pmatrix} \;\xrightarrow{r_3 -= 2r_1,\; r_3 += r_2}\; \begin{pmatrix} 1&1&1\\ 0&4&-1\\ 0&0&-2 \end{pmatrix}\!\begin{pmatrix}6\\5\\-6\end{pmatrix}$$

Back-substitute: x₃ = 3, then 4x₂ − 3 = 5 → x₂ = 2, then x₁ = 6 − 2 − 3 = 1. So x = (1, 2, 3) ✓. Gauss–Jordan keeps going (eliminating above the diagonal too) until A becomes I and the right side is the answer — prettier, ~50% more work, same result.

✏️ Fine print: that forced row swap is not cosmetic — it's pivoting, and with near-zero (not just zero) pivots it's what keeps elimination numerically alive. Efficient but "not necessarily stable" (slides) on near-singular systems — which is where SVD enters below.

7 · LDU: factor once, solve many

$$PA = LDU \qquad \begin{cases} P & \text{permutation: records the row swaps}\\ L & \text{lower triangular, unit diagonal: records the multipliers}\\ D & \text{diagonal: the pivots}\\ U & \text{upper triangular, unit diagonal: pivots divided out} \end{cases}$$

Then \(Ax = b\) becomes three trivial solves: \(Ly = Pb\) (forward), scale by \(D^{-1}\), \(Ux\) (backward). Why bother? Factoring costs ~n³/3 — but it's reusable: each new b afterwards costs only ~n². A controller solving the same-pose system at 1 kHz factors once and streams. (For symmetric positive-definite A, U = Lᵀ — half the work; that's Cholesky's trick.)

LDU is plain Gauss elimination in matrix clothing (below-diagonal only — not Gauss–Jordan). Verified on the slides' A: pivots (2, 4, 1) with the row-swap P.

8 · Eigen-decomposition: solving by dividing

If square A has n independent eigenvectors: \(A = S E S^{-1}\) (S = eigenvectors as columns, E = diagonal eigenvalues). In eigen-coordinates A just stretches each axis by its λ — so solving is dividing each piece of b by its λ:

🕹️ Try it: A = [2 1; 1 2], eigenvalues 3 and 1 (checks: trace 2+2 = 3+1, det 3 = 3×1 ✓). Drag b and watch the recipe.

💡 What it's for: not cheap solving — LU is cheaper. Its value is insight: λ = 0 ⟺ a null direction; tiny λ ⟺ dividing by almost zero ⟺ noise amplification. And it needs n independent eigenvectors, which full rank does not guarantee (e.g. [1 1; 0 1]). It's the seed of SVD, PCA (Lecture 8), stability analysis, and manipulability ellipses.

9 · QR, Gram–Schmidt & least squares

For independent columns, \(A = QR\): Q has A's column space but orthonormal columns (\(Q^TQ = I\)), R is upper triangular. Built by Gram–Schmidt — peel off projections:

$$u_k = v_k - \sum_{j<k} \mathrm{proj}_{u_j}(v_k), \qquad \mathrm{proj}_u(v) = \frac{\langle v, u\rangle}{\langle u, u\rangle}\,u$$

(or via AᵀA's LDU: R = D^{1/2}Lᵀ — the slides' second route). The payoff is over-constrained systems: the least-squares solution \(\bar x = (A^TA)^{-1}A^Tb\) becomes

$$R\bar x = Q^T b \quad\text{(back-substitute)} \qquad\text{— more stable than forming } A^TA$$
Worked example: best line through (1,1), (2,2), (3,2) (click to open)

Fit y = c + mx: A has rows (1, xᵢ), b = (1, 2, 2). Both routes give (c, m) = (2/3, 1/2) ✓ — but on nearly-dependent columns, squaring A (forming AᵀA) squares the condition number; QR avoids ever doing it.

10 · SVD: the universal solvent

$$A = U D V^T, \qquad \sigma_i = \sqrt{\lambda_i(A^TA)}, \quad \sigma_1 \ge \dots \ge \sigma_k > 0,\;\; \text{rank}(A) = k$$

Any m×n matrix, no exceptions. V's columns (eigenvectors of AᵀA) are input directions, U's (eigenvectors of AAᵀ) are output directions, σ's are the gains. Then everything this lecture promised falls out of one formula:

$$x = \sum_i \frac{u_i^T b}{\sigma_i}\, v_i \qquad\qquad \bar x = V\,\tfrac{1}{D}\,U^T b \;\;(\text{zeroing } 1/\sigma_i \text{ for } \sigma_i \approx 0)$$
situationwhat \(\bar x = V\frac1D U^Tb\) gives you
A non-singularthe unique solution
A singular, b reachablethe solution closest to the origin (minimum norm)
A singular, b unreachablethe least-squares solution
Worked example: the slides' near-singular matrix (click to close)

\(A\) = all-ones with 1.01 on the diagonal. Eigenvalues: 3.01, 0.01, 0.01 ✓ — "you barely have full rank". Condition number K = σ₁/σ₃ = 301. Consequence, verified: solving Ax = b with b = (3.01, 3.01, 3.01) gives x = (1, 1, 1); perturb b by just 0.27% and x becomes (2, 1, 0) — an 82% change. Error amplification ≈ the condition number. Gauss elimination happily "succeeds" here; only the σ's warn you.

💡 Why robots care: near-singular is the normal state near kinematic singularities and in poorly-excited calibration data. The σ's are the honest report: tiny σ = a direction your data barely constrains. Zero it out (the slides' advice) and you get the best answer the data actually supports. "You can use SVD for all your needs" — at ~2–3× LU's cost.

11 · Summary

  • Read A·x = b three ways: rows = rules (lines crossing at x), columns = effects (b as a recipe), map = \(\mathbb{R}^n \to \mathbb{R}^m\).
  • Null space = motions the rules can't see; it belongs to the task and the pose; singularity = it appearing unannounced.
  • Elimination solves; pivoting keeps it honest; LDU makes it reusable (n³/3 once, n² per b).
  • Eigen-decomposition is insight, not speed: solving = dividing by λ; tiny λ = sensitivity.
  • QR is the stable path to least squares; SVD is the universal one — rank, null space, condition number, minimum-norm and LSQ solutions, all from the σ's.

🧠 Self-check questions
1 · In the row-view demo, why does changing b never rotate the lines?
A row's coefficients set the line's normal direction (its tilt); b only sets which parallel copy of the line you're on. Rotating a line means changing A — physically, changing the arm's pose.
2 · b = 0 with only a height rule. Is the arm frozen?
No — b = 0 says every listed speed is zero. The hand can slide sideways freely because no rule mentions hand-x. "Zero right-hand side" constrains only what the rows measure.
3 · Columns (0,2) and (0,1): find a null-space vector and say what the arm is doing.
1·(0,2) − 2·(0,1) = 0, so (1, −2) is in the null space: shoulder +1 pushes the hand up 2, elbow −2 pulls it down 2 — one joint undoing the other, hand frozen. Dependent columns ⟺ a cancelling mix ⟺ a null direction.
4 · Why does a 1 kHz controller prefer LDU over just calling solve() each tick?
Same A (same pose, approximately) with a new b each tick: factor once at n³/3, then each tick costs n². Also: controllers re-linearize — J is only exact for small steps, so they re-factor as the pose drifts.
5 · A is full rank. Does the eigen-decomposition A = SES⁻¹ necessarily exist?
No — full rank guarantees invertibility, not n independent eigenvectors. [1 1; 0 1] has rank 2 but one eigendirection. (Symmetric matrices always decompose; the SVD exists for everything.)
6 · Your calibration solve "works" but K(A) = 10⁵. What does that mean operationally?
A 0.001% error in measurements can become a 100% error in parameters (error amplification up to K). Check the σ spectrum, zero the tiny ones (or collect data that excites those directions), and distrust parameters along small-σ directions.
